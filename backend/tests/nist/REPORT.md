# NIST StRD accuracy report

Generated by `tests/nist/make_report.py`; do not edit by hand. Data and certified values are in `tests/nist/data/` (see `SOURCE.md`).

LRE = -log10(|x - c| / |c|), the number of correct significant digits, capped at 15. A value passes when `LRE(ours) >= LRE(baseline) - 0.5`, or when it has at least 14 correct digits (the noise floor of double precision). The baseline is an independent computation: numpy for the univariate statistics; `scipy.stats.f_oneway` (F) and two-pass numpy sums of squares (everything else) for ANOVA. `xfail` is a known, strictly tracked shortfall (see `test_nist_strd.py`). The F shortfall comes from the between sum of squares: pingouin's matches the naive two-pass baseline, and both lose digits on data with a large constant offset (SmLs04 to SmLs09, AtmWtAg), while `f_oneway` centres the data first and keeps about 1.7 digits more. So between SS, between MS and R-squared pass here only because the baseline is equally weak.
